distribution.json 관리 도구

서버 정보 / 모드 / 설정파일 / 배경화면 / 화이트리스트를 입력하고 배포하면 GitHub 저장소에 자동으로 커밋됩니다. 처음 쓴다면 README를 먼저 읽어주세요. 이 도구는 정적 페이지이며 백엔드 서버가 없습니다 — 여러분의 GitHub 토큰은 이 브라우저에만 저장됩니다.

1. GitHub 연결 설정

모드/설정파일/배경화면/아이콘은 서버마다 별도 GitHub 저장소(예: hanol0927/Ssachon)에 올라가고, 각 저장소가 GitHub Pages 프로젝트 사이트로 <도메인>/<저장소명>/에서 서빙되는 구조를 그대로 따릅니다. 토큰에 그 저장소들 각각에 대한 Contents 권한이 있어야 합니다.

3. 서버 정보

기존 서버를 불러오면 아이콘/배경 URL에서 자동으로 채워봅니다. 새 서버라면 GitHub에 미리 만들어둔 저장소 이름을 입력하세요 (없으면 새로 만드세요 — 이 도구가 저장소를 자동으로 만들어주진 않습니다).

3-1. 로더

마인크래프트 버전을 입력하면 자동으로 채워집니다.

GitHub Actions에서 NeoNebula를 실행해 로더를 생성합니다. 처음 쓰는 경우 README의 워크플로우 저장소 설정을 먼저 해주세요. 이 저장소 환경에서 실제로 검증하지 못한 실험적 기능입니다 — 실패하면 아래 "JSON 직접 붙여넣기"로 우회하세요.

4. Java 요구 버전

마인크래프트 버전으로 자동 계산됩니다 (런처 쪽 기본 매핑과 동일한 규칙). 필요할 때만 수동으로 덮어쓰세요.

5. 화이트리스트 (런처 UI에서만 적용, 마인크래프트 서버 접속 자체는 막지 않음)

한 줄에 닉네임 하나씩. 비워두면 전체 허용.

8. 설정 파일 (config)

클릭하거나 설정 파일을 여기로 드래그하세요

저장 경로는 config/ 아래 상대 경로 기준이며, 각 파일마다 직접 수정할 수 있습니다.
"매번 강제 적용"을 체크 안 하면(기본값) 플레이어 폴더에 파일이 이미 있을 때 절대 덮어쓰지 않습니다 — options.txt, iris.properties처럼 플레이어가 직접 바꾸는 설정에 적합합니다. 체크하면 매 실행마다 이 파일로 강제로 되돌립니다.
